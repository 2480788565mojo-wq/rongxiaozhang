# 荣小账 RAG 召回测试报告

## 1. 测试目标

评估当前 `finance_tips` 知识库的召回策略在以下查询上的效果：

- 能否把正确知识召回；
- 正确知识排在第几位；
- 对多跳问题能否同时召回两个知识点；
- 对知识库没有答案的问题，是否错误召回。

本轮只测**召回**，不测 LLM 最终回答质量。

## 2. 测试范围

| 项目 | 内容 |
|---|---|
| 知识库 | `backend/app/rag/seed_data/finance_tips.jsonl` |
| 文档数 | 14 条 |
| 分类 | 餐饮、交通、购物、居住、储蓄、信用卡、保险（各 2 条） |
| 文档类型 | 短建议文本，每条 50–100 字 |
| 查询数 | 27 条 |
| 查询类型 | 精确 5、同义改写 9、长尾 6、多跳 4、负例 3 |
| 评测 K | Recall@1/3/5、Hit@1/3/5、MRR@5 |
| 生产 topK | 3（`insight_service.py` 实际调用） |

## 3. 测试数据与构造方式

查询集：`loadtest/rag_queries.jsonl`。

- 精确查询：直接使用知识中的核心词，例如“信用卡账单日全额还款”。
- 同义改写：换成普通用户说法，例如“每天点奶茶外卖，想省一点伙食费”。
- 长尾查询：带具体数字/情境，例如“月薪八千，房租多少不会压力太大”。
- 多跳查询：需要两个知识点，例如“房租占收入三成，还要存应急金”。
- 负例：知识库没有对应答案，例如“基金定投选什么指数基金”。

### 相关性标注标准

一条文档标为 relevant，当且仅当：

1. 文档直接回答了查询；或
2. 文档提供了该查询所需的核心可执行建议；或
3. 多跳查询中，文档覆盖其中一个必要子问题（多跳要求两个文档都进 gold）。

负例 gold 为空。

### 标注局限

- 查询和标签由单人构造/标注，没有第二标注者和一致性系数。
- 查询是**模拟用户表达**，不是线上真实日志。
- 知识库只有 14 条，topK=3 已覆盖 21% 的库，Recall 会天然偏高。

## 5. 执行步骤

```powershell
cd backend
.\.venv_clean\Scripts\python.exe ..\loadtest\rag_eval.py
```

脚本会：

1. 加载 `finance_tips` Chroma 集合；
2. 若为空则种子写入；
3. 逐条读取 `rag_queries.jsonl`；

5. 计算 Recall@1/3/5、Hit@1/3/5、MRR@5、负例误召回；
6. 写入 `loadtest/rag_eval_results.json`（逐查询记录）。

### 未命中/排名情况

- q10「看到喜欢的东西就想买，怎么控制」：正确 `tip_0004` 排第 2，top1 是 `tip_0005`（价格/使用次数），语义相近。
- 多跳查询 Recall@1 只有 0.5，是因为一个查询有两个 gold，top1 只能命中一个；但 **Hit@1=1.0**，且两个 gold 都在 top3，说明排序可接受。
- K=5 相比 K=3 没有提升（Recall@3 已经是 1.0），当前 14 条库下 top3 足够。

## 7. 判定标准与结论

### 建议阈值

| 指标 | 达标线 | 实测 | 结论 |
|---|---:|---:|---|
| Recall@3 | ≥ 0.90 | 1.000 | ✅ |
| Hit@3 | ≥ 0.95 | 1.000 | ✅ |
| MRR@5 | ≥ 0.85 | 0.979 | ✅ |
| 负例 False Positive@3 | ≤ 0.20 | 1.000 | ❌ |

### 结论

**已知问题的召回合格，但“不知道时不要乱召回”不合格。**

原因：`retrieve_relevant_tips` 永远返回 topK 文档，没有距离阈值、相关性判断或拒答机制；Chroma 总会给出最近邻。对基金、信用卡提额、车险比价这类库外问题，仍会把相邻主题当成知识注入。

## 8. 优化建议

### P0：加相关性门槛/拒答

- 对 top1/top3 的 cosine distance 设阈值；当前正例 top1 最大约 0.420，负例 top1 最小约 0.374，**单纯一个距离阈值无法完全分开**，需要：
  - 距离阈值 + top1/top2 间隔；
  - 或加一个小型 cross-encoder/LLM 相关性判定；
  - 或按分类过滤后再判断。
- 负例误召回应从 100% 降到 ≤20% 再上线面向用户的“建议”功能。

### P1：扩充并版本化知识库

- 当前只有 14 条短文本，测试结果不能代表真实知识库。
- 至少补到 100–300 条，覆盖更多长尾/负例。
- `seed_finance_tips` 在集合非空时直接返回，**修改 seed 文件不会自动重建索引**；需要加版本号/重建命令，否则线上仍用旧知识。

### P1：真实查询集

- 从脱敏后的真实用户问题中抽样 100–200 条，做双人标注。
- 当前查询集是模拟数据，存在构造偏差。

### P2：分块与过滤

- 若文档变长，按 300–500 字、50 字重叠分块。
- 查询若已带分类（餐饮/交通等），加 metadata filter 提升精度。
