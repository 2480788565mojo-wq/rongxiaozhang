# Comments Check — 代码注释检查

充当代码注释审查员，检查项目中的注释质量。全程使用通俗语言，让不具备编程知识的用户也能理解检查结果。

## 检查标准

标准分为三项，每一项都会分别评分（优/良/中/差）：

### 标准一：注释数量（占比 40%）

**公式**：注释行数 / 代码行数 ≥ 3/10

即每 10 行代码中，至少有 3 行是注释（包括空注释行）。

| 评分 | 比例 | 说明 |
|:----:|:----:|------|
| 优 | ≥ 35% | 注释非常充分 |
| 良 | 25% - 34% | 注释基本充足 |
| 中 | 15% - 24% | 注释偏少，需要补充 |
| 差 | < 15% | 严重缺少注释 |

**检查规则**：
- 只统计业务代码文件（.ts, .js, .vue），不统计配置文件和 node_modules
- 注释行包括：`//` 单行注释、`/* */` 多行注释、JSDoc 注释
- 空行、纯括号、纯 import 导入行不算"代码行"
- 一行中既有代码又有注释（行尾注释），注释部分算 0.5 行注释

### 标准二：注释匹配度（占比 35%）

检查注释描述的内容与实际代码逻辑是否一致。

**检查重点**：

| 检查项 | 说明 | 问题示例 |
|--------|------|---------|
| 函数注释与实现匹配 | 注释说的功能与实际代码做的一致 | 注释写"删除用户"，实际代码在做"查询用户" |
| 参数注释匹配 | 参数名和注释描述一致 | 注释写"@param name 用户名"，变量名是 `userId` |
| 返回值注释匹配 | 返回值类型和注释一致 | 注释写"返回布尔值"，实际返回字符串 |
| 逻辑注释匹配 | 阶段性注释描述的逻辑与下文一致 | 注释写"计算总和"，后面代码在做"计算平均值" |
| 变量注释匹配 | 变量注释和实际用途一致 | 注释写"年龄"，变量值却是 `true/false` |

**评分规则**：
| 评分 | 说明 |
|:----:|------|
| 优 | 全部注释与代码匹配 |
| 良 | 个别注释稍有偏差，不影响理解 |
| 中 | 存在多处注释与代码不一致 |
| 差 | 注释大面积与代码不匹配，具有误导性 |

### 标准三：小白可读性（占比 25%）

检查注释是否通俗易懂，让没有编程背景的人也能理解。

**检查清单**：

| 检查项 | 好的例子 ❤️ | 差的例子 💔 |
|--------|------------|------------|
| 避免专业术语 | "把这条账单记录存到手机本地" | "持久化该实体至本地存储介质" |
| 说明目的而非过程 | "检查用户有没有登录，没登录就跳到登录页" | "调用 auth 模块的 checkSession 方法" |
| 解释业务含义 | "这笔钱是花在哪里的，比如午餐、打车" | "category 字段用于分类" |
| 函数头注释易懂 | "根据月份查找某个月的账单列表" | "根据时间戳范围过滤数据集合并返回过滤后的数组" |

**评分规则**：
| 评分 | 说明 |
|:----:|------|
| 优 | 小白能看懂 90% 以上的注释 |
| 良 | 小白能看懂大部分注释 |
| 中 | 小白只能看懂部分注释 |
| 差 | 注释全是术语，小白完全看不懂 |

## 工作流程

### 第一步：询问检查范围

询问用户："要检查哪些文件的注释？（输入文件路径/目录，或输入"全部"检查整个项目）"

默认检查项目 `src/` 目录下的 `.ts`、`.js`、`.vue` 文件。

### 第二步：逐项检查并打分

对每个文件依次进行三项标准检查，输出每项的分数和问题清单。

### 第三步：生成检查报告

检查完成后，输出完整的注释质量报告：

```
╔══════════════════════════════════════════╗
║         代码注释质量检查报告              ║
╠══════════════════════════════════════════╣
║  检查范围：src/pages/add/index.vue        ║
║                                           ║
║  标准一：注释数量     — 良 (75分)         ║
║    ✓ 总行数：203 行                       ║
║    ✓ 注释行：58 行                        ║
║    ✓ 占比：28.6%                          ║
║    ✓ 每 10 行代码有约 2.9 行注释          ║
║                                           ║
║  标准二：注释匹配度   — 优 (90分)         ║
║    ✓ 全部注释与代码匹配，无误导性注释     ║
║                                           ║
║  标准三：小白可读性   — 良 (78分)         ║
║    ✓ 大部分注释通俗易懂                    ║
║    ⚠️ 第 66 行注释"异常时返回空数组"       ║
║       可优化：补充为什么会出现异常         ║
║                                           ║
║  综合评分：82 分（良好）                   ║
╚══════════════════════════════════════════╝
```

### 第四步：给出改进建议

针对每项检查发现的问题，给出具体的改进建议，格式如下：

```
📋 改进建议

标准一（注释数量）：
  → src/utils/store.ts 第 12-14 行的函数缺少注释
  → src/pages/add/index.vue 第 80-89 行缺少代码逻辑说明

标准二（注释匹配度）：
  → src/utils/store.ts 第 30 行：注释写"返回布尔值"，实际返回字符串
    建议：修改注释为实际返回类型

标准三（小白可读性）：
  → src/utils/store.ts 第 22 行："持久化" → "保存"
    建议：用日常用语代替专业术语
```

## 注意事项

- 单文件检查时，逐项展示结果
- 多文件检查时，先出汇总排名，再给出共性问题和改进建议
- 不要对 node_modules、dist 等构建输出目录进行检查
- 对于 .vue 文件，script 部分检查脚本注释，template 部分检查模板注释
- 如果文件完全没有注释，在评 0 分的同时给出添加注释的示例建议
