# Unit Test — 自动单元测试

充当测试助手，帮您为项目代码创建测试、执行测试并给出报告。全程用通俗语言，让不懂测试的用户也能理解。

## 工作流程总览

```
检查测试环境（安装必要工具）
    → 扫描代码，列出可测试的文件
    → 自动生成测试代码（您确认后写入）
    → 执行全部测试
    → 输出测试报告
```

## 第一步：检查测试环境

运行以下检查项，缺一不可：

### 1.1 检查 vitest 是否已安装

运行 `npx vitest --version`：
- 如果成功 → 已安装，跳过
- 如果失败 → 询问用户："这个项目需要安装测试工具包，是否要安装？（约 20MB）"
  - 用户同意 → 执行 `npm install -D vitest @vue/test-utils happy-dom`

### 1.2 检查测试配置文件

检查项目根目录是否存在 `vitest.config.ts`：
- 如果不存在 → 自动创建 vitest.config.ts 配置文件，内容如下：

```typescript
import { defineConfig } from 'vitest/config'
import uni from '@dcloudio/vite-plugin-uni'

export default defineConfig({
  plugins: [uni()],
  test: {
    environment: 'happy-dom',
    include: ['src/**/*.test.ts'],
  },
})
```

### 1.3 检查 package.json 是否有测试脚本

检查 `scripts` 中是否包含 `"test"`：
- 如果不存在 → 在 package.json 的 scripts 中添加：`"test": "vitest run"` 和 `"test:watch": "vitest"`

## 第二步：扫描并选择要测试的文件

扫描 `src/` 目录下的所有 `.ts` 和 `.vue` 文件（排除配置文件），列出给用户：

```
找到以下可测试的文件：
1. src/utils/store.ts（工具函数）
2. src/pages/add/index.vue（记账页）
3. src/pages/bills/index.vue（账单列表）
4. ...

要为哪些文件创建测试？（输入序号，多个用逗号分隔，或输入"全部"）
```

等待用户选择。

## 第三步：生成测试代码

根据用户选择的文件，自动生成对应的 `.test.ts` 测试文件，生成规则：

### 3.1 对于 .ts 工具函数文件（如 store.ts）

分析文件中的每个函数/方法，为每个函数生成测试，覆盖以下场景：

| 测试类型 | 说明 | 例子 |
|---------|------|------|
| ✅ 正常情况 | 传入正常值，期望返回正确结果 | 添加一笔账，能查出来 |
| ⚠️ 边界情况 | 传入极限值，期望正确处理 | 金额为0、为负数、超大数字 |
| ❌ 异常情况 | 传错参数，期望优雅报错 | 不传参数、传 null |

### 3.2 对于 .vue 页面/组件文件

分析页面中的核心功能，生成组件渲染和交互测试：

| 测试类型 | 说明 | 例子 |
|---------|------|------|
| ✅ 页面渲染 | 页面能正常显示出来 | 页面标题、按钮存在 |
| ✅ 用户交互 | 点击按钮、输入内容能正常工作 | 点击"保存"触发保存逻辑 |
| ⚠️ 边界情况 | 空数据、极限数据时页面表现 | 账单列表为空时显示"暂无记录" |

### 3.3 写入测试文件

在源文件同级目录下创建 `.test.ts` 文件。写入前**展示给用户确认**：

```
即将为 store.ts 创建测试文件 → src/utils/store.test.ts
包含 6 项测试：
  ✅ 正常添加一条支出记录
  ✅ 查询某月的账单列表
  ⚠️ 添加金额为 0 的记录
  ⚠️ 删除不存在的记录
  ❌ 传入空数据
  ❌ 传入类型错误的数据

确认写入？(Y/N)
```

用户确认后才写入文件。

## 第六步：补充说明

### 测试文件放哪里？

所有测试文件放在被测试文件旁边，例如：
```
src/utils/store.ts         ← 源文件
src/utils/store.test.ts    ← 测试文件
```

### 以后怎么自己跑测试？

- `npm run test` — 执行全部测试（一次性）
- `npm run test:watch` — 监听模式，改了代码自动重新跑测试

### 测试文件能删除吗？

可以，直接删除对应的 `.test.ts` 文件即可，不影响项目运行。
