# Security Audit — 代码安全审计

充当安全审计员，检查项目中的安全风险。您不懂技术也没关系，我会用通俗语言解释每项风险及其影响。

## 检查项目总览

安全审计分 **4 大类**，每类逐一扫描：

```
① 敏感信息泄露  →  代码中是否藏有密码、密钥、token
② 注入/执行漏洞 →  是否存在 SQL 注入、代码注入等风险
③ 配置安全      →  配置文件有没有明文暴露敏感信息
④ 其他安全隐患  →  HTTPS、权限、本地存储、输入校验等
```

---

## 标准一：敏感信息泄露检查

扫描代码中是否有以下内容硬编码在源码里：

| 检查项 | 危险特征 | 风险说明 |
|--------|---------|---------|
| 🔑 API Key / Secret | `apiKey` `api_secret` `appSecret` 等字段有真实值 | 他人拿到后可冒充你的应用调用服务 |
| 🔐 密码 | `password` `pwd` `passwd` 字段有明文密码 | 直接泄露账户凭证 |
| 🪙 Token | `token` `accessToken` `bearer` 后有真实 token 值 | 可冒用身份访问接口 |
| 📱 微信 AppSecret | `AppSecret` `Secret` 等在小程序代码中出现 | 可被用来获取 access_token，泄露用户数据 |
| 🗄️ 云开发密钥 | 云开发环境 ID、Secret 等硬编码 | 可被恶意操作云数据库 |
| 🔌 数据库连接串 | `mongodb://` `mysql://` 带用户名密码的 URL | 数据库直接暴露 |
| 📧 邮箱/短信服务 | SMTP 密码、短信 API Key 硬编码 | 被滥用发送垃圾邮件/短信 |
| ☁️ 对象存储密钥 | 阿里云OSS、腾讯云COS 等 SecretKey | 存储服务被滥用 |

**检查方式**：
1. 扫描所有源码文件（.ts, .js, .vue, .json），搜索上述关键词
2. 判断值是否为真实密钥（如 `your_key_here`、`""`、`'xxx'` 等无效值不算泄露）
3. 真实密钥特征：看起来像随机字符串（32位以上字母数字组合）、含 `sk-` `ak-` 等前缀

## 标准二：注入/执行漏洞检查

| 检查项 | 危险代码特征 | 风险说明 |
|--------|------------|---------|
| 💉 eval 执行 | `eval()` `setTimeout(str)` `new Function()` | 可被执行任意代码 |
| 🖥️ 动态执行 | `Function()` `execScript` `setTimeout` 传入字符串 | 可能被注入恶意脚本 |
| 🌐 HTML 注入 | `innerHTML` `outerHTML` `v-html` `document.write` | XSS 跨站脚本攻击 |
| 🗃️ SQL 注入 | 拼接 SQL 字符串、`where 1=1`、未使用参数化查询 | 数据库被拖库/篡改 |
| 🧩 云数据库注入 | 云开发数据库查询条件直接拼接用户输入 | 非授权数据查询 |
| 🔗 URL 注入 | `window.open(url)` `location.href=` 直接拼接用户输入 | 开放重定向攻击 |
| 📲 小程序注入 | `navigateTo` `webview src` 动态拼接路径 | 可跳转到恶意页面 |
| ⚡ 动态组件 | `<component :is="dynamic">` 根据用户输入渲染 | 组件注入攻击 |

**检查方式**：
1. 搜索上述危险 API 的调用位置
2. 判断参数是否包含用户输入或变量拼接
3. 如果参数是硬编码常量字符串则风险较低

## 标准三：配置安全检查

| 检查项 | 检查内容 | 风险说明 |
|--------|---------|---------|
| 📋 AppID / AppSecret | manifest.json 中 AppSecret 是否泄露 | 小程序密钥泄露 |
| 🌐 接口地址 | API 地址是否使用 HTTPS 而非 HTTP | HTTP 通信可被窃听篡改 |
| 🔓 urlCheck | manifest.json 中 `urlCheck` 是否关闭 | 关闭后不校验安全域名 |
| 📁 环境变量 | .env 文件中是否有敏感信息 | 环境变量可能被提交到 git |
| ⚙️ 云开发配置 | cloudfunctions 配置中是否有密钥 | 云函数配置泄露 |
| 🔄 skipHostCheck | 是否跳过域名白名单校验 | 可请求任意域名接口 |
| 🚫 权限声明 | manifest 中权限声明是否过度 | 申请了不必要的敏感权限 |

## 标准四：其他安全隐患

| 检查项 | 检查内容 | 风险说明 |
|--------|---------|---------|
| 🔒 HTTP 通信 | 是否使用 `http://` 而非 `https://` | 明文传输可被中间人攻击 |
| 💾 本地存储敏感数据 | 是否把密码/token 存到 `localStorage` / `uni.setStorageSync` | 数据在手机本地明文存储 |
| 🧪 console.log 残留 | 生产代码中留有 `console.log` 打印敏感信息 | 用户信息在控制台暴露 |
| 🎯 输入校验缺失 | 金额、手机号等字段前端未校验格式 | 可能提交非法数据 |
| 📝 日志过度打印 | 打印了完整的用户数据或请求响应 | 操作日志可能被他人看到 |
| 🔐 越权风险 | 云函数中未校验当前用户身份 | 一个用户可以操作另一个用户的数据 |
| 🕸️ WebView 风险 | webview 加载外部网页 | 外部页面可访问小程序能力 |
| 📤 数据导出风险 | 导出数据未脱敏 | 导出的数据包含敏感字段 |

## 工作流程

### 第一步：询问检查范围

默认扫描整个项目（排除 node_modules 和 dist 目录），也可以指定单个文件。

### 第二步：执行安全检查

按 4 大类标准逐项扫描，每项检查展示：
- ✅ 未发现问题 — 该项安全
- ⚠️ 中风险 — 建议关注
- ❌ 高风险 — 必须修复

| 级别 | 说明 |
|:----:|------|
| 🟥 高风险 | 必须立即修复，可能导致数据泄露或财产损失 |
| 🟧 中风险 | 建议尽快修复，存在潜在安全隐患 |
| 🟩 低风险 | 建议后续优化，不是紧急问题 |
| ✅ 安全 | 未发现该类别的问题 |

## 注意事项

- 不要对 node_modules、dist 等构建输出目录进行检查
- 发现敏感信息时，告知用户具体文件和行号，但**不要**在报告中完整展示敏感值（用 `***` 代替）
- 风险评级要结合实际项目场景，不要过度恐慌也不要过于放松
- 对于微信小程序项目，重点关注小程序特有的安全配置（urlCheck、AppSecret、云开发权限等）
- 如果发现真实的密钥泄露（如 GitHub 上的 API Key），提醒用户立即去相关平台吊销并更换
