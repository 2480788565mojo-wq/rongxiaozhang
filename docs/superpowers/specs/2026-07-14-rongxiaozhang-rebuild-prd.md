## 1. 产品概述

### 1.1 产品定位

**荣小账**是一款 AI 驱动的智能记账微信小程序。不同于传统记账工具繁琐的手动填表模式，荣小账通过自然语言交互实现"一句话记账"，并在消费瞬间提供实时预算风控，同时支持多人共享账本与智能 AA 结算，最终通过深度数据分析为用户提供个性化的省钱决策建议。

**一句话描述**：说出来就能记，花钱就有人管，多人一起用不乱，还能告诉你该怎么省。

### 1.2 产品愿景

让每个人都能像和朋友聊天一样管理自己的财务——不需要学习记账知识，不需要养成记账习惯，不需要计算复杂的分摊。AI 替你完成所有繁琐的工作，而你只负责做出更好的消费决策。

### 1.3 核心价值主张

| 传统记账 | 荣小账 v2.0 |
|---------|------------|
| 打开 APP → 选类型 → 输金额 → 选分类 → 选账户 → 填日期 → 写备注 → 保存 | 说一句"午饭湘菜68块"，AI 自动解析并确认 |
| 月底看报表才发现超支 | 消费前实时告警："本月餐饮已用 95%，确定还要花吗？" |
| 群收款算半天还吵起来 | 自动算出最优 AA 方案：谁该给谁多少钱，一笔不多一笔不少 |
| 看了一堆图表不知道怎么改进 | AI 告诉你"减少外卖每周自带午餐 3 次，月省 ¥600" |

### 1.4 解决的四大痛点

| # | 痛点 | 用户原话 | 荣小账方案 |
|---|------|---------|-----------|
| 1 | **记账太麻烦** | "每次记账要点七八下，坚持不了三天" | 自然语言/语音一句话记账 + AI 自动填表 |
| 2 | **超支后才知道** | "每次都月底看账单才后悔，早该控制" | 消费前毫秒级预算检查 + 实时告警弹窗 |
| 3 | **AA 算账头疼** | "出游三天算账算了两小时还觉得不对" | 共享账本 + 图论最优债务抵消 + 一键结算 |
| 4 | **不知道问题在哪** | "看了饼图知道吃太多，但不知道怎么办" | AI 深度分析 + 理财知识库 + 可执行省钱策略 |

## 2. 市场背景与竞品分析

### 2.1 市场机会

- 中国个人记账 APP 用户规模超过 **2 亿**，但 **次日留存率普遍低于 30%**
- 核心流失原因：**记账操作繁琐**（占流失用户的 68%）
- 微信小程序月活 **13 亿**，是记账工具的最佳载体（无需下载、即用即走）
- AI 大模型成熟，特别是中文自然语言理解和 Function Calling 能力已达商用水平

### 2.2 竞品对比

| 维度 | 随手记 | 鲨鱼记账 | 钱迹 | 薄荷记账 | **荣小账 v2.0** |
|------|--------|---------|------|---------|----------------|
| 记账方式 | 手动填表 | 手动+模板 | 手动 | 手动+语音 | **AI 自然语言** |
| 预算风控 | 事后报表 | 事后提醒 | 无 | 事后图表 | **事前毫秒级拦截** |
| 多人协同 | 无 | 无 | 无 | 简单共享 | **分布式锁+图论AA** |
| AI 洞察 | 无 | 无 | 无 | 无 | **RAG+深度推理** |
| 平台 | APP | APP+小程序 | APP | APP | **微信小程序优先** |
| AI 技术深度 | — | — | — | — | **LangGraph 多Agent** |

**差异化结论**：荣小账 v2.0 是国内首个将多 Agent 协作深度集成到记账场景的产品，在"录入便利性""实时风控""多人协同""智能决策"四个维度全面领先。

### 5.2 AI 记账功能详解

**输入方式**：
1. **文本输入**：在输入框打字，支持口语化表达
2. **语音输入**（v2.1）：调用微信原生语音识别，转文字后送入 AI 解析

**支持的自然语言表达示例**：

| 用户输入 | AI 解析结果 |
|---------|-----------|
| "午饭湘菜68块" | 支出、¥68、餐饮美食·中餐、今天 |
| "今天打车花了35" | 支出、¥35、交通出行·打车、今天 |
| "昨天发了工资8000" | 收入、¥8000、工资收入、昨天 |
| "和同事AA聚餐，我付了240" | 支出、¥240、餐饮美食·聚餐，备注"AA" |
| "信用卡还了2000" | 支持自定分类/备注 |
| "给女朋友买了礼物150" | 支出、¥150、人情社交·送礼 |

**反问场景**：
| 用户输入 | AI 反问 |
|---------|--------|
| "吃了个饭" | "请问花了多少钱？" |
| "花了68块" | "这是哪类消费？（如餐饮、交通、购物等）" |

**隐私保护**：所有语音和文本仅在用户设备端和加密传输到服务器处理，不做任何第三方共享。

### 5.3 预算风控功能详解

**预算设置**：
- 按月设置总预算
- 按分类设置子预算（9 大支出分类每个可单独设）
- 支持修改（当月修改立即生效）

**告警时机**：在 AI 解析完成、用户点击"确认记账"时触发

**告警级别**：

| 级别 | 触发条件 | 视觉效果 | 用户操作 |
|------|---------|---------|---------|
| 🟢 安全 | < 80% | 无提示 | 正常记账 |
| 🟡 警告 | 80% ~ 99% | 黄色弹窗 + 分类 + 剩余金额 | 点击"仍然记账"继续 |
| 🔴 拦截 | ≥ 100% | 红色全屏 + 分类 + 超支金额 | 点击"仍然记账"二次确认 |

### 5.4 多人协同功能详解

**账本类型**：
- **个人账本**：每个用户默认拥有，仅自己可见
- **共享账本**：创建者邀请他人加入，所有成员可记账和查看

**成员角色**：
- **Owner（创建者）**：完全控制权，可管理成员、删除账本
- **Admin（管理员）**：可记账、查看、邀请新成员
- **Member（成员）**：可记账、查看

**AA 结算流程**：
```
1. 成员 A 在共享账本中记账 ¥300，选择"5 人 AA"
2. 系统自动生成 5 条分摊记录（每人 ¥60）
3. 月底点"结算"，系统计算净额并输出最优转账方案
4. 方案示例："B → A ¥60, C → A ¥60, D → A ¥60, E → A ¥60"
5. 各成员确认转账后在 APP 内标记"已结算"
```

**债务抵消效果**：
- 10 人出行 3 天，20 笔交叉支付
- 传统方式：可能需要 20+ 笔互相转账
- 荣小账算法：压缩到 5-8 笔转账

## 7. 用户体验设计

### 7.1 设计原则

1. **语音优先（Voice First）**：AI 记账页是默认入口，填表是降级方案
2. **渐进式披露**：不一次性展示所有功能，按场景逐步引导
3. **即时反馈**：每次操作有明确的状态变化（解析中 → 解析完成 → 告警 → 成功）
4. **科技感美学**：深色主题选项 + 渐变色 + 微妙动效 + 原子化设计系统

### 7.2 关键页面流程

#### 核心流程：AI 记账

```
首页 → 点击 "+" 或 Tab "记账"
     → AI 记账页
     → 输入 "午饭湘菜68块"
     → [解析中... 动画]
     → 展示解析结果卡片（金额/分类/时间）
     → [可选] 点击任意字段修改
     → 点击 "确认记账"
     → [若超预算] 弹出告警 → 点击 "仍然记账"
     → 绿色勾 + "记账成功" → 首页数据刷新
```

#### 共享账本流程

```
我的页 → 账本管理 → 创建共享账本
     → 输入名称（如"我们的家"）
     → 生成邀请码
     → 微信分享给好友
     → 好友扫码/点击 → 加入账本
     → 成员记账时选择该共享账本
     → 自动记录成员身份 + 支持 AA 分摊
     → 月末发起结算 → 查看债务方案 → 确认结清
```

## 8. 数据与隐私

### 8.1 数据收集原则

- **最小化收集**：仅收集记账必需的数据
- **透明化使用**：AI 功能明确告知数据用途
- **用户可控**：可导出全部数据、可永久删除账号及数据

### 8.2 数据分类

| 数据类型 | 具体内容 | 存储位置 | 保留期限 |
|---------|---------|---------|---------|
| 账户信息 | 微信 openid、昵称、头像 | MySQL | 账号存续期 |
| 记账数据 | 金额、分类、时间、备注 | MySQL | 账号存续期（用户可删除） |
| AI 对话 | 自然语言输入、AI 反问、解析结果 | MySQL | 30 天滚动删除 |
| 洞察报告 | AI 生成的消费分析 | MySQL | 最近 12 个月 |
| 语音数据 | 用户语音输入 | 不存储（仅实时转文字） | 处理后立即删除 |

### 8.3 数据安全措施

- 数据库访问：仅限后端内网访问，不暴露公网端口
- API 鉴权：每个请求验证 JWT + 资源归属
- 微信云托管：数据库自动备份 + 7 天回滚
- 日志脱敏：不记录用户具体消费内容到日志

## 11. 风险与应对

| # | 风险 | 影响 | 概率 | 应对措施 |
|---|------|------|------|---------|
| 1 | LLM API 服务不稳定或涨价 | 核心功能不可用 | 中 | 双 Provider 容灾（DeepSeek+Qwen）；预留手动填表降级方案 |
| 2 | 微信小程序审核不通过 | 无法发布 | 低 | 提前自查审核指南；AI 生成内容增加免责声明 |
| 3 | 用户担心隐私（消费数据被 AI 分析） | 信任度下降 | 中 | 隐私政策透明化；AI 处理数据不用于训练；提供数据删除功能 |
| 4 | 高并发下 Redis 或 MySQL 瓶颈 | 响应变慢 | 低 | 云托管自动扩容；Redis Cluster 分片预留方案 |
| 5 | AI 解析准确率不达标 | 用户体验差 | 中 | HITL 反问机制兜底；持续优化 Prompt；收集 bad case 迭代 |
| 6 | 用户增长过快导致成本失控 | 现金流压力 | 低 | 设置 LLM API 调用频率限制；按需扩容而非预留资源 |
| 7 | 共享账本并发写冲突 | 数据不一致 | 低 | Redis 分布式锁保障；冲突时提示"稍后重试" |
